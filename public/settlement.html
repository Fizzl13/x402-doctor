x402 payment proof check

After a paid x402 request, the seller answers with a PAYMENT-RESPONSE header (X-PAYMENT-RESPONSE in x402 v1). Paste it here to see which on-chain transaction it points to, whether that transaction exists and succeeded, and which USDC moved from whom to whom.

Paste the header

Free and read-only: nothing is signed or paid, and the header isn't stored.

Where to find the header

  • curl: add -i to the paid request and copy the value after payment-response:.
  • JavaScript: res.headers.get('payment-response') (or x-payment-response for v1 sellers).
  • A browser: developer tools → Network → the paid request → Response headers.

What it tells you

  • In plain x402 one paid request is one signed authorization, one settlement and one transaction. The header names it: transaction, network, payer and success.
  • A hosted checkout (such as a payment session) adds its own ids on top; those live in that provider's backend. The transaction hash is still the link to the chain.
  • Not found? Check the network. A payment for Base won't show a transfer made on Solana, and the other way round.

Before paying, check the endpoint itself with the free x402 Doctor check, or its track record in the Trust Index.

API: POST /api/settlement with {"header": "…"} (free, rate-limited). The same check is in x402 Doctor's MCP server as check_payment_proof. To look a transaction up directly, link to /settlement?tx=<hash>&network=<CAIP-2> (the Fizzl Agent Wallet does this from its receipts).
